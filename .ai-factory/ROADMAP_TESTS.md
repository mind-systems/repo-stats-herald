# Test Roadmap

> Cover the surfaces that fail silently — the ones that keep running and produce wrong output — and leave the rest to the compiler, the runtime, and HTTP.

A coverage pass over the whole codebase grouped it into candidate areas, dropped every area that fails loudly or is already covered, and researched the eleven that survived. Each entry below implements one of those areas against its plan; the plans hold the case lists, the fixture patterns to reuse, and the gotchas, and are the artifact to read before starting. Twenty areas were deliberately dropped and are not coming back through the side door: the delivery-plan resolver, the three Postgres stores, both source strategies, the reasoner family, the versioner and the report engine, the webhook and release fan-out, the coordination seeder, the code distiller and the delivery clients are covered; the GitHub release client, the App auth, the summariser, the translator and every composition root fail loudly.

Gating: the seams these tests need are in place — the commit log parses from a string, the mirror takes a process runner, and both model clients take a transport. Every entry here is writable against the code as it stands, and no entry here edits `src/`. Where the research found a defect rather than a gap, it belongs to the main roadmap and is tested there by the task that fixes it; the generator's absent response validation is the one such case that came out of this pass.

Discipline: a test here exists because a wrong answer would otherwise arrive looking right. Where an entry's plan pins current behaviour that is arguably wrong — the chunker's unclosed-fence merge, the report-schedule parser's per-character sections, the collector dropping a commit whose subject holds a record separator — pin it as it is and note it. Changing it is a separate decision, made deliberately, not smuggled in behind a test.

- [x] **Markdown chunker** — `chunk_markdown` (`src/knowledge/chunker.py`) has two tests against 129 lines, and a boundary bug degrades every retrieval touching a document with plausible-looking chunks and no exception. Untouched today: the preamble branch, the heading-less document, empty input, the shallowest-level split rule, the exact size boundary, the whole paragraph-grouping fallback, and all of the code-fence machinery that gates every heading decision. Pure function, no I/O, no fixtures — every case is a string literal and one call, which makes this the cheapest coverage in the pipeline. Guard: size fixtures build against the imported constant, never a literal; do not assert a universal upper bound on chunk length — an over-limit single paragraph is deliberate; pin the unclosed-fence merge as current behaviour and flag it. Spec: `.ai-factory/specs/79-markdown-chunker-test-plan.md`. [10m 20s]
- [x] **Settings parsing & DSN** — `src/core/config.py` carries four hand-written validators and the production DSN, with three incidental assertions covering any of it. A mis-parsed value yields a valid-looking `Settings` that serves the wrong orgs, posts to the wrong chat, or seeds the wrong graph edges — no crash, no log line. Cover the allowlist, the JSON-dict key coercion across all four fields, the edge grammar, the schedule parser, and DSN composition. Guard: pass `_env_file=None` everywhere, since `make test` exports `.env.dev` and any assertion about a default is otherwise machine-dependent; the schedule parser's raw `TypeError`/`KeyError` escape pydantic and must be caught as themselves; the DSN case asserts the byte-identical no-reserved-character form, which survives 19.2 rather than colliding with it. Spec: `.ai-factory/specs/70-settings-parsing-test-plan.md`. [9m 17s]
- [x] **KnowledgeSync canonical-ref gate** — `src/knowledge/sync.py` is the only writer that keeps semantic memory equal to "what the project is now", and nothing tests it. Its gate is the sole thing stopping a feature branch from overwriting that answer, silently. Cover the gate in both directions, the override-versus-default-branch resolution, changed-path derivation across a multi-commit push, deletion of removed curated paths, the tree opened at the push SHA rather than the ref name, and both backfill walks. Guard: assert sets, never call order — the changed-path collection is unordered; the mirror fake's `tree` is a sync context manager; the non-canonical case must assert the source strategy was never even consulted. Spec: `.ai-factory/specs/71-knowledge-sync-test-plan.md`. [10m 41s]
- [x] **EpisodicWriter** — `src/ingestion/writer.py` turns a served push into exactly one episodic entry and has no test. Its hazard is the write-side half of the one already pinned at the store: a timestamp taken from the ingest moment rather than the head commit collapses history into "now", plausibly and without error. Cover timestamp provenance, field mapping, what text is embedded, the code-only push, the single-append guarantee, and that the store is never read at write time. Guard: assert the stored timestamp is far from now, not merely equal to the fake's return, or the test cannot tell a correct implementation from a wall-clock read; give the push payload and the resolved commits deliberately different text so a source mix-up is visible. Spec: `.ai-factory/specs/72-episodic-writer-test-plan.md`. [13m 39s]
- [x] **ArtifactIndexer** — `src/knowledge/indexer.py` decides whether a source becomes memory, and an inverted selection branch either indexes orchestrator plan-noise or silently drops a governing artifact, with no crash either way. Cover the selection gate, the chunk-embed-upsert wiring and its ordering, the degenerate and error paths, and removal. Guard: the layers below are already pinned by their own suites — do not re-test selection rules, chunk boundaries, or store semantics here; assert only the orchestration this class owns. Spec: `.ai-factory/specs/74-artifact-indexer-test-plan.md`. [6m 58s]
- [x] **CodeBootstrap draft-path invariant** — `src/knowledge/bootstrap.py` writes a machine-generated, unreviewed draft, and its whole safety rests on that path being one no source strategy selects; if it ever were, the sync would auto-index the draft on the next canonical push and poison memory with no error. The constructor guard checks only the artifact strategy, leaving the code strategy unchecked. Assert the invariant directly against both strategies, plus the single-file write, the no-clobber re-run, and the unreviewed marker. Guard: import the draft-path constant, never retype it, or the invariant test survives an edit to the constant and proves nothing. Spec: `.ai-factory/specs/75-code-bootstrap-test-plan.md`. [7m 44s]
- [x] **ServedRepoStore** — `src/ingestion/served_repos.py` holds the set the reporting run iterates, and no test touches it or the installation branch that writes it. A deletion scoped too widely drops other orgs' repos with no error and no log line — they simply stop being reported. Cover idempotent add, org-scoped removal, the ordering `all` promises, the empty-iterable guards that run on nearly every installation event, and convergence under replayed events. Reuse the Postgres fixture pattern the graph, knowledge and episodic suites already share, in a new ingestion conftest. Guard: populate a second org in every removal case, or an over-broad predicate passes on a single-tenant fixture; the router's installation branch is a separate concern and stays out. Spec: `.ai-factory/specs/76-served-repo-store-test-plan.md`. [10m 25s]
- [ ] **GitCommitCollector — the commit-log parse** — twelve tests cover the collector's ranges, tags and ancestry; none covers `collect`, whose parse feeds every prompt, the linked-change resolver and the backfill. A misparsed statistic is wrong prose, never an error. Split the file: a parse group driving `parse_log` with captured text constants — record framing, injection through the commit body, brace-compressed renames, merge commits, large statistics blocks — and a collect group on the existing repository fixtures that keeps checking git's real output against the parser. Guard: `new_commits`' failure signal belongs to 18.2.x and stays untouched; the non-ASCII path case is now a positive assertion; the record-separator case is **out of scope** — it asserts behaviour that does not exist, and belongs to 23.6 in the main roadmap, which lands it with the framing fix. Spec: `.ai-factory/specs/77-commit-collector-parse-test-plan.md`.
- [ ] **RepoMirror — lifecycle, refs and disk state** — two tests cover the mirror, both concurrency-only, leaving clone-versus-fetch, force-push adoption, ref pruning, worktree reclamation timing, default-branch resolution and the startup sweep unpinned. A default branch resolving wrong means indexing the wrong branch as "what the project is now"; a sweep reaching too widely removes state quietly. Scope: everything in the plan except the credential group, which is its own entry. Guard: never assert a worktree is gone right after its block exits — deferred reclamation is the contract, and a cleanup-on-exit assertion would be red against correct code; assert disk and git's own worktree list separately, since they can disagree; concurrency and the async conversion belong to 20.2.x and stay out. Spec: `.ai-factory/specs/78-repo-mirror-surface-test-plan.md`.
- [ ] **RepoMirror — credential handling** — on an http clone source the installation token travels through the process environment and must stay out of the argument list, out of the persisted remote, and out of the text and attributes of the raised failure. That guarantee returns no value and leaves no artefact, and the filesystem clone source the fixtures use never takes the branch, so nothing has ever checked it. Construct the mirror with a recording runner and assert on what git was actually asked to run, plus the real-run check that the token never lands in the bare store's config. Scope: the plan's credential group only; the lifecycle group is its own entry. Guard: the recorder must return a completed-process object, since the default-branch read takes stdout off it. Spec: `.ai-factory/specs/78-repo-mirror-surface-test-plan.md`.
- [ ] **EpisodicBackfill — history walk and derivation mode** — `src/episodic/backfill.py` replays a repo's whole history and re-decides per step whether to derive from the roadmap or from the code; nothing tests it. Three hazards, all silent: the mode decided once at HEAD instead of per historical tree derives a whole era wrongly, a non-idempotent re-run duplicates entries, and a run-moment timestamp collapses the history it exists to preserve. Drive it against a real mixed-history repository built by fixture. Guard: set both author and committer dates on every fixture commit, or the test reproduces the timestamp hazard inside itself and passes for the wrong reason; the introducing commit is artifact-mode, so assert the exact split rather than "some of each"; put fixture code under a real source root or the code strategy selects nothing and the distillation case silently never distils. Scope: the git-only suite; the store round-trip is its own entry. Spec: `.ai-factory/specs/73-episodic-backfill-test-plan.md`.
- [ ] **EpisodicBackfill — store round-trip** — the in-memory idempotency check cannot see duplicated rows, and the windowed query over backfilled history is the end-to-end proof that historical timestamps really landed as historical. Cover both against a real database, in a module separate from the git-only suite so that suite keeps running without one. Guard: the fake store's recorded-SHA lookup must compute the same union the real store does, or the sibling entry pins a weaker invariant than production. Scope: the plan's store round-trip group only. Spec: `.ai-factory/specs/73-episodic-backfill-test-plan.md`.
- [ ] **Ollama clients — transport-driven suite** — `src/llm/client.py` and `src/llm/embedder.py` have no tests at all. The embedder's five response checks are two-line guards with nothing holding them in place, and a wrong or missing vector poisons retrieval ranking without any crash. Establish `tests/llm/`, then cover the embedder's validation, the batching contract — empty input issues no request, all texts go in one, vectors come back positionally aligned — and request composition and transport failure for both clients. Guard: drive everything through the injected transport with real response objects; do not hand-write a client stand-in, and never let a test reach the network — a missed transport hangs for the full timeout and then fails looking like a legitimate error assertion. Scope: the plan's generator response-parsing group is **not** part of this entry — that surface has no assertable behaviour until the generator refuses an empty answer, so it belongs to 23.5 in the main roadmap, which lands those cases with the fix and establishes `tests/llm/` before this entry starts. Spec: `.ai-factory/specs/80-ollama-clients-test-plan.md`.
