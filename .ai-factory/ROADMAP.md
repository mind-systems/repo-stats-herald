### Phase 3 — Repo mirror & semantic memory

Herald keeps no copy of a repo, yet every phase built on it *replays over one* — diffs, roadmap `[ ]→[x]` transitions, tag history, and back-merge detection are all local git ops, today for semantic indexing and later for episodic memory, releases, and the reports. Herald authenticates as the App (App JWT → per-org installation token, cached, doubling as the git credential) and keeps a generic full local mirror of each served repo, pulled on each push. The mirror is dumb plumbing: no sparse-checkout, no per-project file policy — *which* files matter is task 3.4's call, never the mirror's. See [understanding: freshness](../docs/spec/understanding.md#freshness-is-tied-to-git).

Semantic memory is the standing per-project model of what a project *is now* — its features, direction, and built-vs-remaining state, distilled from the artifacts it already curates. Pinned: the store holds current state, not history — the history is the episodic memory, built later; retrieval is a lens over the store, not a store type of its own; the embedder is fixed per store, so a model swap never forks the index. See [per-project knowledge model](../docs/spec/understanding.md#per-project-knowledge-model).

### Phase 4 — Episodic memory (the evolution log)

Blocked on Phase 3 (the mirror and the semantic model both live there). This is the half of memory the old plan lacked: **episodic memory**, the append-only log of *how* a project changed. The derivation engine resolves each push to its linked change — the intent (the roadmap task) and the change (the commits) — and appends it; the outcome (the feature that moved) is narrated from that record at read time, not stored. Each entry is retained across supersession and removal, so a feature that once existed and was later dropped stays recoverable. Retrieval over the log answers "what was this, when did it change, why was it removed" — the memory that makes Herald a partner about a project's past, not just its present. Pinned: the event stream is the source of truth; semantic memory is its current projection, episodic memory its history; both are retrievable. See [architecture: the two engines](../docs/architecture.md#the-two-engines-over-the-event-stream).

### Phase 6 — Project graph & the cross-project surface

Blocked on Phase 3 (retrieval and the semantic model both live there). Most cross-project ties are written down in the projects' own docs and surface through retrieval; the graph holds only what retrieval cannot — undeclared couplings (a configured registry of directed, typed edges) and the edges a coordination root declares about its members and contracts (seeded; `source=config` never overwritten by `seed`). Neighbor discovery unions retrieval with the graph, with no surface heuristic — that guess is where hallucination starts. This is the always-on cross-project awareness both memories and the reasoner draw on. See [understanding: project graph](../docs/spec/understanding.md#project-graph).

### Phase 16 — Historical replay (backtest)

Blocked on the whole broadcast slice — episodic backfill and code-derivation (Phases 4–5), the reasoner (7), narration (8), Telegram delivery (9), the reporting engine (10), and versioning windows (11) — and deliberately sits last: replay orchestrates finished parts instead of threading a new concern through their tasks. Today a repo Herald starts serving gets its past *indexed* (4.4) but never *narrated* — no one can open the channel and read how the project grew. Replay drives the derivation engine over the repo's history in simulated time — semantic memory tracks the replay cursor, not `HEAD` — cutting a report every N active (non-empty) days and a release-style note at each historical version tag, delivered with historical dates to a Telegram channel designated at launch; the channel becomes the project's chronicle, and the run doubles as end-to-end acceptance of both narration types over a real history. Pinned: memory writes idempotent across re-runs while narration regenerates fresh (texts are a projection of memory, not part of it); runs boundable (K windows / stop at a commit) for small-dose checks; N is a launch parameter (15 ≈ sprint, 30 ≈ monthly); no outward effect beyond Telegram — no tags, GitHub releases, or changelog writes. Behavioral contract: [replay](../docs/spec/replay.md).
