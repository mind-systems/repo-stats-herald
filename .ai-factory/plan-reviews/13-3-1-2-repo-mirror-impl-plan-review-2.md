Factoring subprocess details into a private `_run_git` helper with `check=True, capture_output=True` mirrors the fixture's `_git` and keeps git specifics inside `RepoMirror`.

- Affects: task 3.4.2 / 3.6 (the consumer, prod http path only) — passing the installation token via `git -c http.extraheader="Authorization: Basic <base64>"` places it in process argv, briefly visible to other host processes (e.g. `/proc`/`ps`). This satisfies the spec's stated guard (never in `origin` URL, never logged) and the http branch is never exercised by any current test (all fixtures use local `clone_source`), so it is out of scope here. When the consumer wires real HTTPS clone sources on a shared host, prefer a stdin/env credential form (e.g. a one-shot credential helper) over argv if argv exposure matters in that deployment.
