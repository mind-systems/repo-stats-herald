### Critical Issues

**1. Task 5 — `git clone --bare` + `git fetch --prune origin` does not refresh refs on the second `ensure()`; the mirror silently goes stale.**
A plain `git clone --bare <source>` copies branch heads directly but configures **no** `remote.origin.fetch` refspec (git's own docs: "neither remote-tracking branches nor the related configuration variables are created"). I reproduced this on git 2.50.1: after a `--bare` clone, advancing the upstream and running `git -C bare.git fetch --prune origin` fetches only into `FETCH_HEAD` — `refs/heads/trunk` stays pinned at the old commit. Consequences:
- Governing-spec Verification #2 ("a second call fetches, doesn't re-clone") — the fetch runs but brings nothing current, so a re-pushed repo is never updated.
- The **force-push tolerated** guard (spec Guards; ROADMAP "force-push tolerated") — a force-moved ref is never picked up.
- The freshness contract the mirror exists to serve (`understanding.md#freshness-is-tied-to-git`, ROADMAP line 30).

Crucially, **the pinned tests will not catch this** — `test_mirror_isolation.py` calls `ensure()` exactly once (clone path only), so the suite goes green while the fetch path is broken. The plan's literal wording (and the spec's line 16) both say `--bare`, so the implementer will faithfully produce broken refresh.

Fix: give the bare store a mirror refspec. `git clone --mirror <source> <bare_path>` sets `remote.origin.fetch = +refs/*:refs/*` (still a full clone — satisfies the no-sparse/no-partial guard) and, verified on 2.50.1, `git -C <bare> fetch --prune origin` then advances local refs and prunes deleted ones correctly. Equivalent alternatives: keep `--bare` but explicitly `git config remote.origin.fetch '+refs/heads/*:refs/heads/*'` after clone, or fetch with an explicit refspec `git -C <bare> fetch --prune origin '+refs/heads/*:refs/heads/*'`. Any of these will still pass 3.1.1's clone-only isolation test. Recommend the plan pin `--mirror` (or the explicit refspec) instead of a bare `--bare`, and note this as a deliberate deviation from the spec's imprecise `--bare` wording so the spec's own Verification #2 actually holds.

### Positive Notes
- **`Settings` field types made optional with defaults (Task 2) is a correct, well-reasoned deviation from the spec's `github_app_id: int` / `...: str`.** I confirmed the mechanism: `tests/conftest.py` sets only `GITHUB_WEBHOOK_SECRET`/`SERVE_ALLOWLIST` and clears `get_settings`' cache; the webhook `TestClient` then builds `Settings()`. Adding *required* App/mirror fields would raise `ValidationError` and break the already-green webhook suite — exactly what Verification bullet 2 ("full suite stays green") forbids. Defaults + "composition root asserts before building the mirror" is the least-invasive choice. The `field_validator`/`NoDecode` block is correctly left untouched, and `.env.example` already documents `GITHUB_APP_ID`/`GITHUB_APP_PRIVATE_KEY_PATH` (only `MIRROR_ROOT=` is new, as the plan states).
- **The single-flight design is faithful to the test contract.** Double-checked locking under a per-org lock, `token()` synchronous and wrapping the retained `_mint_token(org_id) -> str`, `_mint_token` monkeypatchable — this makes the 8-caller barrier mint exactly once and return one distinct string, matching `test_app_auth_single_flight.py`. Using `time.monotonic()` for expiry (independent of the wall-clock `time.time()` used for the JWT `iat/exp`) is correct.
- **The local-vs-http credential gate is the right read of the tests.** `conftest.py`'s `auth` is the real stub (`token()` raises `NotImplementedError`, not monkeypatched), and `clone_source` returns a local filesystem path. The plan's "call `auth.token()` only when the source scheme is `http`/`https`" is exactly what keeps the isolation tests from failing for the wrong reason, and passing the token per-command via `http.extraheader` (never into `origin`) satisfies the "never persisted/never logged" guard.
- **`tree()` mechanics are sound and I verified the riskiest step.** `git worktree add --detach <scratch> <ref>` into an *existing empty* `mkdtemp` directory works on git 2.50.1 (a real historical gotcha — confirmed not an issue here). `--detach` correctly avoids the same-ref branch-checkout collision; per-worktree `remove --force` in `finally` (not a blanket prune) preserves a concurrent open sibling, matching `test_teardown_of_one_tree...`; guarding cleanup so a removal error can't mask an in-body exception, plus `worktree prune` in `ensure` for crash-orphans, covers the leak-hygiene guard.
- **Task 7's docstring-only composition-root note is the correct call** given the webhook receiver that would consume `RepoMirror` is not built (CLAUDE.md status), avoiding dead wiring in `main.py`.
